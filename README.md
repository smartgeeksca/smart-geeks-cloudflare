# Smart Geeks -- Cloudflare Pages site

A static site build for Smart Geeks, an independent electronics repair and
buy-sell-trade business in Surrey, BC. Built as plain Python-templated HTML
+ vanilla CSS/JS, deployed as a Cloudflare Pages project with Pages
Functions for the contact form.

## Quick start

```bash
python3 build.py          # generates the full static site into public/
python3 tests/qa.py       # runs the automated QA suite against public/
python3 -m http.server 8000 --directory public   # preview locally
```

No dependencies beyond the Python 3 standard library are required to build
or test the site. (Pillow was used once, already, to generate the favicon
PNGs in `src/assets/icons/` via `scripts/generate_brand_assets.py` -- you
only need to rerun that script if you change the brand mark itself.)

For actual Cloudflare deployment steps, environment variables, and the
email-provider setup, see **DEPLOYMENT.md** -- including three ways to
deploy, none of which require installing Wrangler: connecting a Git repo
(Cloudflare's own build servers run `python3 build.py` for you), plain
dashboard drag-and-drop of the `public/` folder, or drag-and-drop plus the
pre-written `alt-deploy/_worker.js` bundle if you want the contact form and
noindex middleware working without Git either. See DEPLOYMENT.md
"Three ways to deploy (none require Wrangler)" for the full comparison.

## Design reference disclosure

Per the brief, `https://www.smartgeeks.ca/` was inspected this session (via
a live fetch) and used **only** as a structural/UI reference -- general
conventions like a sticky header with logo/nav/phone CTA, a headline +
subhead + dual-CTA hero, a card-grid services section, and a multi-column
footer. No text, images, or markup were copied; every word of content in
this package is original, and all CSS/HTML implementing those structural
conventions was authored from scratch. See "Note on the reference site" below.

### Note on the reference site

The live `www.smartgeeks.ca` fetched during this build displays the same
business name and phone number given in the brief, but a noticeably
different scope and set of claims than this package's content rules allow:
consumer phone/tablet repair and full managed-IT/MSP services (outside this
build's scope, which is limited to the device categories in the brief), and
marketing claims this package deliberately does not carry over --
"Trusted since 2016," a "5.0/5 Google rating," "50+ repairs weekly," "no
diagnosis fees," and student/senior discounts. None of those claims are
verifiable from this session, so none of them appear anywhere in this
package (see the "Quality and Reliability Rules" section of the original
brief -- no invented years-in-business, ratings, review counts, or free
diagnostics). **Before this build replaces what's currently live, the
owner should confirm which claims on the current site are accurate and
decide whether/how to reintroduce any of them (with real, verifiable
figures) -- see "Owner action items" below.**

## Project structure

```
smart-geeks-cloudflare/
├── src/
│   ├── data/            # business.py (single source of truth for facts),
│   │                       schema.py (JSON-LD builders)
│   ├── content/         # services.py, pages.py, legal.py, landing.py --
│   │                       all page copy lives here, not in build.py
│   ├── templates/       # layout.py -- shared HTML shell, header, footer,
│   │                       breadcrumbs, FAQ accordion, cards, CTA blocks
│   └── assets/           # css/, js/, images/, icons/, icon_glyphs.py
├── functions/
│   ├── api/contact.js    # Pages Function: contact form handler
│   └── _middleware.js    # Pages Function: non-production noindex header
├── scripts/
│   ├── generate_brand_assets.py   # one-time favicon/OG-image generator (already run)
│   └── check_worker_sync.py       # verifies alt-deploy/_worker.js hasn't drifted from functions/*.js
├── alt-deploy/
│   └── _worker.js         # OPTIONAL: self-contained bundle for no-Git, no-Wrangler
│                             drag-and-drop deploys with the contact form still working
│                             -- see DEPLOYMENT.md "Option C"
├── public/                # BUILD OUTPUT -- regenerated by build.py, don't hand-edit
├── tests/
│   └── qa.py              # automated QA suite (see QA-REPORT.md for last results)
├── build.py                # the static site generator
├── wrangler.toml
├── _headers / _redirects    # copied into public/ by build.py
├── .dev.vars.example
├── .python-version
├── DEPLOYMENT.md
├── CONTENT-INVENTORY.md
├── IMAGE-ASSET-MANIFEST.md
├── QA-REPORT.md
├── CHANGELOG.md
└── LICENSE-NOTICE.md
```

This is a small, deliberate deviation from the suggested structure in the
brief: there's no separate `src/pages/` directory, because pages are
*generated* by functions in `build.py` that combine `src/content/*` (copy)
with `src/templates/layout.py` (markup) -- there's no static per-page
template file to put there. `tests/` contains one QA script rather than a
unit-test framework, since there's no client-side application logic complex
enough to warrant one; `tests/qa.py` is the meaningful test surface for a
content-driven static site.

## Centralized data

Every business fact (address, phone, email, socials, brand colors,
analytics IDs) lives in **`src/data/business.py`**. Content, templates, and
JSON-LD schema all import from it, so there is exactly one place to update
if the phone number changes or a real GA4 ID becomes available -- nothing
is hand-duplicated across pages.

## Content and compliance rules this build follows

- **No fabricated facts.** No invented prices, repair turnaround times,
  certifications, manufacturer authorization, awards, review
  counts/ratings, years-in-business, guarantees, warranty durations,
  opening hours, financing, free diagnostics, or success rates appear
  anywhere in this package. Where a fact isn't available yet (hours,
  warranty duration, diagnostic fee), the relevant page says so honestly
  instead of guessing or leaving a placeholder -- see "Owner action items."
- **Independent-business disclosure** appears on every Mac-related page and
  in the footer sitewide: Smart Geeks is not Apple- (or any other
  manufacturer-) authorized or affiliated.
- **No people in imagery.** No photography was available this session (see
  IMAGE-ASSET-MANIFEST.md); a CSS-based brand placeholder is used instead of
  a fabricated photo, and the manifest lists exactly what real photography
  to add later, with no layout change required.
- **Google Ads policy:** landing-page copy avoids known trigger phrases
  ("tech support," "remote support," "unlock/jailbreak," "virus removal,"
  "data recovery") and makes no urgency/guarantee claims. Separately,
  Google's Third-Party Consumer Technical Support policy explicitly lists
  hardware repair services as a restricted ad category requiring account
  certification -- that's an account-level Google Ads setup step, not
  something page copy alone resolves. See "Owner action items."

## Owner action items

These cannot be completed truthfully without input only the business owner
can provide. The build is complete and deployable without them -- each one
has a safe, honest default in the meantime (see the relevant file):

| Item | Where it's handled today | File to update |
|---|---|---|
| Real opening hours | Not stated anywhere; pages direct visitors to call/WhatsApp to confirm | Add hours content once confirmed; wire into `src/data/business.py` and any page that should display them |
| Genuine reviews / review source link | Reviews page links out to Google Maps rather than displaying curated quotes | `src/content/pages.py` -> `REVIEWS_PAGE`, `src/data/business.py` -> `maps_url` |
| Warranty duration | Warranty policy explains coverage exists without stating a duration | `src/content/legal.py` -> `WARRANTY_POLICY`, `src/data/business.py` -> `OWNER_PENDING["warranty_period"]` |
| Diagnostic fee | Diagnostic policy explains fees are communicated before work begins, without a figure | `src/content/legal.py` -> `DIAGNOSTIC_POLICY` |
| Real store/workbench photography | CSS-based brand placeholder frames | See IMAGE-ASSET-MANIFEST.md |
| Real service prices | Not published; pages explain pricing is quoted after diagnostics | `src/content/legal.py`, `src/content/services.py` |
| GA4 measurement ID | Analytics scripts don't load at all until set | `src/data/business.py` -> `ANALYTICS_CONFIG["ga4_measurement_id"]` |
| Google Ads conversion ID/labels | Same as above | `src/data/business.py` -> `ANALYTICS_CONFIG` |
| Transactional email provider credentials | Contact form fails safely with an honest error until configured | See DEPLOYMENT.md "Email delivery setup" |
| Google Ads hardware-repair certification | Landing pages avoid policy trigger phrases, but certification is an account-level step this project can't complete | Google Ads account, not this codebase |
| Final privacy/legal review of policy pages | Drafted in good faith, explicitly flagged as not lawyer-reviewed | `src/content/legal.py` |
| Confirm domain ownership / "Finding Zero" | See README "Note on the reference site" above | Business decision, not a code change |
