# Brutal Design Review — Smart Geeks (Pre-V3)

A candid critique of the site as it stood before this pass (the Design System V2 state: clean, accessible, well-engineered, but still reading as "a good local repair website"). Written as if handed to design reviewers at Apple, Stripe, Vercel, and Linear. Technical quality (accessibility, performance, SEO, code hygiene) is explicitly out of scope here — all of that was already strong. This is about *perception* only.

---

**What a Stripe reviewer would say:** "Everything is correctly spaced and nothing is memorable. Stripe pages work because a handful of specific decisions — the gradient mesh, the mono numerals in the pricing tables, the restrained one-accent-color discipline — recur everywhere until they *become* the brand. Your previous version had good bones (a real 8px scale, real elevation tokens) but every section used the same white-card-on-white-page pattern. There's no signature. I could show me ten different local-business templates and I wouldn't be able to tell which one was yours."

**What a Linear reviewer would say:** "Your type scale tops out at 2.75rem. Linear's marketing headline is functionally the loudest thing on the page — it's allowed to dominate, because confidence is part of what you're selling. Your hero read at the same visual volume as your body copy. Also: no dark surface anywhere except the CTA band. Linear (and most of this category) uses dark, technical, grid-lined surfaces as a *recurring motif*, not a one-off footer color. A single dark section reads as 'we ran out of ideas for that one part'; four dark sections sharing one visual language reads as 'this is intentional.'"

**What a Vercel reviewer would say:** "Where's the technical texture? Companies like this earn trust by *looking* like they understand hardware at a component level — grid lines, schematic/blueprint motifs, mono type for anything numeric or technical. Your placeholder image blocks were a good instinct (better than stock photography) but they were decorative, not *legible* as 'this business thinks in circuits.' A repair shop has more license to use genuinely technical visual language than almost any other local-business category, and the site wasn't using it."

**What an Apple reviewer would say:** "The copy is honest and the layout is calm, which I respect — but calm isn't the same as considered. Every heading uses the same weight and the same font as the body text, just bigger. There's no typographic hierarchy beyond size. A page can be quiet and still feel expensive; yours was quiet and felt plain, because there was only one lever (size) being pulled."

**Common thread across all four:** none of these are complaints about competence — the accessibility work, the zero-fabrication content discipline, and the component engineering underneath were all already sound. The complaint is that a well-built, honest local-business site and a premium technology brand can share the same underlying HTML/CSS architecture and still look completely different, and this one hadn't made the choices that separate them: a true hero-scale headline, a signature dark surface used more than once, a technical/mono typographic accent, and an asymmetric (not uniformly-gridded) layout somewhere on the page. All four of those were fixed in this pass — see the Design System V3 spec (doc 05) for what actually shipped in response to each point above.
